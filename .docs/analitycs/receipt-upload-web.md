# AN-002 — Загрузка чеков через сайт вместо Telegram-бота

**Status:** `approved`  
**Owner:** аналитик  
**Created:** 2026-11-07  
**Updated:** 2026-11-07  
**Related tasks:** `TASK-002`

## 1. Контекст и проблема

Сейчас новые изображения чеков принимает Telegram-бот. На временный период бот необходимо полностью остановить, но пользователи должны продолжать загружать чеки и получать результат обработки через сайт.

## 2. Цель и ожидаемый результат

Пользователь может загрузить изображение чека через сайт, после чего оно попадает в существующий OCR/LLM конвейер.

| Метрика | Текущее значение | Целевое значение | Способ проверки |
|---|---:|---:|---|
| Загрузка чека через сайт | отсутствует | 1 изображение создаёт 1 чек | ручная проверка API/UI |
| Работа Telegram-приёма | включена | полностью выключена | проверка конфигурации и запуска |
| Обработка уже созданных чеков | работает | продолжает работать | проверка фоновых сервисов |

## 3. Область решения

### Входит

- временное отключение Telegram polling конфигурационным флагом;
- сохранение работы OCR и LLM фоновых сервисов;
- API загрузки изображения через `multipart/form-data`;
- форма загрузки на сайте;
- создание `Receipt` со статусом `Created` и записью истории;
- поддержка текущего списка чеков без авторизации.

### Не входит

- авторизация и разграничение доступа пользователей;
- отправка чека по email, в Telegram или экспорт в PDF;
- изменение OCR/LLM алгоритмов;
- удаление Telegram-интеграции.

## 4. Требования и ограничения

- Telegram-бот по умолчанию не запускается, но может быть возвращён настройкой.
- Изображение должно быть непустым и иметь поддерживаемый image content type.
- Загруженный файл сохраняется в S3/MinIO, а в БД создаются чек и история `Created`.
- Временное решение использует технический `OwnerKey` для веб-загрузок.
- Текущий API остаётся без авторизации; это известное ограничение, не предназначенное для публичного production-доступа.

## 5. Варианты решения

| Вариант | Плюсы | Минусы | Рекомендация |
|---|---|---|---|
| Веб-загрузка через существующий API и pipeline | минимум изменений, переиспользование обработки | пока нет пользовательской авторизации | да |
| Полностью удалить Telegram-код | меньше активного кода | сложное восстановление и потеря интеграции | нет |
